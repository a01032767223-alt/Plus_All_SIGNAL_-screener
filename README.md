# 매수신호 자동 스크리너

국내주식(KOSPI·KOSDAQ) 전종목, 미국주식(S&P500 + 나스닥100), 업비트 KRW 코인을
매일 자동으로 훑어서
**이동평균선 · 거래량 · 지지저항 · RSI · MACD · 볼린저밴드 · ADX · OBV** 8개 지표로
점수를 매기고, 폰에서 볼 수 있는 대시보드와 텔레그램·이메일 알림으로 보내줍니다.

각 시장 탭 안에는 "매수신호"와 별개로 **"추세전환"** 탭도 있습니다 — 장기간
하락하던 종목이 하락을 멈추고 상승으로 돌아서는 **초기 구간**을 가격구조·
거래량·모멘텀·이동평균·변동성(코인은 BTC 대비 상대강도까지) 6개 카테고리로
점수화해, "초기 진입"과 "확인 진입"으로 구분해 보여줍니다. 자세한 내용은
[추세전환 초기탐지](#추세전환-초기탐지--새-탭-추세전환) 섹션을 보세요.

세 번째로 **"내 전략"** 탭에서는 이 점수의 **지표별 반영 비중을 직접 조절**할 수
있습니다. 슬라이더를 움직이면 스캔한 **전 종목**이 그 비중으로 즉시 다시 줄 세워져,
기본 목록에 없던 종목이 새로 올라옵니다. 자세한 내용은
[내 전략](#내-전략--지표-비중을-직접-조절하는-탭) 섹션을 보세요.

서버가 필요 없습니다. GitHub Actions(무료)가 실행하고 GitHub Pages(무료)가 보여줍니다.

## 설치 — 처음 한 번만, 15분

### 1단계. 리포지토리 만들기

1. GitHub에서 **New repository** 클릭
2. 이름: `signal-screener` (원하는 이름 가능)
3. **Private** 선택해도 됩니다. 단, Pages를 무료로 쓰려면 **Public**이 편합니다.
   (Private 리포의 Pages는 유료 플랜 필요 → **Public 권장**)
4. README 추가 옵션은 **체크 해제**하고 생성

### 2단계. 코드 올리기

**방법 A — 명령어 (권장)**

```bash
cd signal-screener            # 압축을 푼 폴더로 이동
git init
git add .
git commit -m "매수신호 스크리너 초기 설정"
git branch -M main
git remote add origin https://github.com/<내아이디>/signal-screener.git
git push -u origin main
```

**방법 B — 웹에서 드래그**

리포지토리 화면 → `uploading an existing file` → 폴더 안 파일 전체를 끌어다 놓기 →
`Commit changes`
※ `.github` 폴더는 숨김 폴더라 드래그로 누락되기 쉽습니다. 방법 A를 권합니다.

### 3단계. GitHub Pages 켜기

`Settings` → 왼쪽 `Pages` →
- **Source**: `Deploy from a branch`
- **Branch**: `main` / 폴더는 **`/docs`** 선택 → `Save`

1~2분 뒤 주소가 나옵니다: `https://<내아이디>.github.io/signal-screener/`

> **폴더를 `/docs`가 아니라 `/ (root)`로 설정해도 됩니다.**
> 리포지토리 루트에 있는 `index.html`이 자동으로 `docs/`로 넘겨주므로 어느 쪽을 골라도 동작합니다.
> (`/docs`를 고르면 루트의 `index.html`은 그냥 사용되지 않습니다)
>
> | Pages 폴더 설정 | 실제로 열리는 파일 | 대시보드 주소 |
> |---|---|---|
> | `/docs` (권장) | `docs/index.html` | `.../signal-screener/` |
> | `/ (root)` | `index.html` → `docs/index.html`로 이동 | `.../signal-screener/` (자동 이동) |

### 4단계. Actions 권한 열기

`Settings` → `Actions` → `General` → 맨 아래 **Workflow permissions** →
**Read and write permissions** 선택 → `Save`
(결과 파일을 리포에 다시 커밋해야 하므로 필요합니다)

### 5단계. 알림 설정

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

#### 텔레그램 (5분)
1. 텔레그램에서 **@BotFather** 검색 → `/newbot` → 이름 정하고 나면
   `123456:ABC-DEF...` 형태의 **토큰**을 줍니다
2. 방금 만든 내 봇을 찾아 대화창을 열고 **아무 메시지나 한 번 보냅니다** (필수)
3. 브라우저에서 아래 주소 접속 → `"chat":{"id":123456789` 숫자가 **채팅 ID**
   `https://api.telegram.org/bot<토큰>/getUpdates`
4. Secret 두 개 등록

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1번의 토큰 |
| `TELEGRAM_CHAT_ID` | 3번의 숫자 |

#### 이메일 (Gmail)
1. Google 계정 → 보안 → **2단계 인증**을 먼저 켜야 합니다
2. [앱 비밀번호](https://myaccount.google.com/apppasswords) 생성 → 16자리 발급
3. Secret 세 개 등록

| 이름 | 값 |
|---|---|
| `GMAIL_USER` | 보내는 Gmail 주소 |
| `GMAIL_APP_PASSWORD` | 16자리 앱 비밀번호 (띄어쓰기 제거) |
| `MAIL_TO` | 받을 주소 (쉼표로 여러 개 가능) |

#### 대시보드 링크 (알림에 첨부됨)
같은 화면의 **Variables** 탭 → `New repository variable`

| 이름 | 값 |
|---|---|
| `PAGES_URL` | `https://<내아이디>.github.io/signal-screener/` |

> 설정하지 않은 채널은 조용히 건너뜁니다. 텔레그램만 써도 되고 둘 다 써도 됩니다.

### 6단계. 첫 실행

`Actions` 탭 → 왼쪽에서 **국내주식 스크리닝** → `Run workflow` → `Run workflow`

야후가 한 번에 수십 종목씩 주기 때문에 전종목이 **2~5분**이면 끝납니다.
(증분 캐시를 쓰지 않고 매번 전체를 새로 받습니다 — 캐시가 꼬여서 틀린 값이 남는 것보다
매번 새로 받는 편이 안전합니다.)
끝나면 텔레그램에 알림이 오고 대시보드에 결과가 뜹니다.

**미국주식 스크리닝**, **코인 스크리닝**도 동일하게 `Run workflow` 로 한 번씩
돌려보세요. 대시보드의 각 탭은 해당 워크플로를 한 번이라도 돌려야 채워집니다.
(미국주식은 550~600종목이라 1~3분이면 끝납니다.)

### 7단계. 폰 홈화면에 앱으로 추가

- **아이폰**: Safari로 Pages 주소 접속 → 공유 버튼 → `홈 화면에 추가`
- **안드로이드**: Chrome으로 접속 → 우측 상단 ⋮ → `앱 설치` 또는 `홈 화면에 추가`

주소창 없이 앱처럼 열리고, 비행기 모드에서도 마지막 결과를 볼 수 있습니다.

> GitHub Actions 크론은 서버 부하에 따라 **5~20분 늦게** 시작되는 일이 흔합니다. 정상입니다.

데이터 날짜(`data_date`)는 한국 날짜가 아니라 **미국 현지 날짜**로 찍힙니다.

## 데이터 소스

| 대상 | 종목 목록 | 시세 |
|---|---|---|
| 국내주식 | FinanceDataReader → (실패 시) 네이버 시가총액 페이지 | 야후 일괄 다운로드 → (수집률 저조 시) 네이버 siseJson |
| 미국주식 | S&P500: GitHub CSV → FinanceDataReader → 내장 스냅샷<br>나스닥100: 위키백과 → 내장 스냅샷 | 야후 일괄 다운로드 |
| 코인 | 업비트 `/v1/market/all` | 업비트 캔들 API (4시간/일/주) |

**KRX를 쓰지 않는 이유** — 2025년 12월 27일부터 KRX 정보데이터시스템이 회원 로그인 필수로
바뀌었습니다. 거래소가 밝힌 사유는 "AI 봇의 무단 데이터 수집으로 인한 서버 과부하"입니다.
로그인 없이 호출하면 JSON 대신 로그인 페이지가 돌아와 `pykrx`도 함께 막혔습니다.
그래서 로그인이 필요 없는 야후·네이버·FinanceDataReader 조합으로 대체했습니다.

야후는 한 번에 수십 종목을 받아오므로 전종목이 수십 초면 끝납니다. 덕분에 증분 캐시 없이
매번 전체를 새로 받아도 되고, 캐시가 꼬여서 생기는 문제가 원천적으로 사라졌습니다.

주 소스가 죽으면 대체 경로로 자동 전환하고, 어느 소스를 썼는지 로그에 남깁니다.
양쪽 다 실패하면 명확한 안내와 함께 중단합니다.

> **소스가 또 막히면** `.github/workflows/probe.yml`(데이터소스 진단)을 수동 실행하세요.
> 실행 서버에서 16개 소스(국내·미국·코인)에 실제로 접속해보고 ✅/❌ 요약표를 출력합니다.

**미국주식 유니버스를 S&P500 + 나스닥100으로 잡은 이유** — 러셀 소형주까지 넣으면
6,000종목이 되는데, 야후 데이터 품질이 들쭉날쭉하고 유동성이 얕아 지표가 쉽게 왜곡됩니다.
국내 증권사 앱에서 살 수 없는 종목도 많습니다. 550~600종목이면 수집이 1~2분이면
끝나고 국내 투자자가 실제로 매매 가능한 범위와 거의 일치합니다.

목록 소스가 전부 막혀도 모듈 안에 내장된 스냅샷으로 돌아갑니다. 스냅샷이 조금 낡아
상장폐지된 티커가 섞이면 야후에서 조용히 누락될 뿐 파이프라인은 멈추지 않습니다.

## 점수 체계

| 영역 | 지표 | 가중치 | 핵심 조건 |
|---|---|---|---|
| 추세 | 이동평균선 | 25% | 20MA > 60MA + 가격이 20MA 위 |
| 수급 | 거래량 | 20% | 상승 시 거래량 ≥ 평균의 1.5배 |
| 가격구조 | 지지·저항 | 20% | 저항 돌파 또는 주요 지지선 반등 |
| 모멘텀 | RSI | 10% | 30~50에서 상승 전환 |
| 모멘텀 | MACD | 8% | 골든크로스 + 히스토그램 증가 |
| 변동성 | 볼린저밴드 | 7% | 하단 반등 또는 수축 후 상단 돌파 |
| 추세강도 | ADX | 5% | ADX > 20~25 + +DI > −DI |
| 수급보조 | OBV | 5% | OBV 상승 추세 (매집) |

각 지표는 O/X가 아니라 **0~100점의 연속값**으로 계산합니다. 그래야 순위가 의미를 갖습니다.
등급은 **S 85+ / A 75+ / B 65+ / C 55+**.

**타임프레임**: 국내주식·미국주식은 일봉 70% + 주봉 30%,
코인은 4시간봉 25% + 일봉 50% + 주봉 25%.
모든 타임프레임이 60점을 넘으면 **정렬 보너스 +5점**.

## 매도·경계 신호 (⚠)

총점은 "매수 조건에 얼마나 부합하는가"의 가중합입니다. 이동평균·거래량·가격구조
3개가 비중 65%를 차지하기 때문에, 이 셋이 강하면 RSI·MACD·OBV가 전부 반대
신호를 보내도 총점 자체는 통과선을 넘을 수 있습니다. 추세는 아직 살아있지만
단기 과열로 꺾이기 시작한 "천장 근처" 종목이 대표적인 예입니다.

그래서 점수를 깎거나 종목을 목록에서 빼는 대신, 8개 지표를 매수 관점의 정반대로
다시 훑어서(`screener/rules.py`의 `sell_signals()`) 걸리는 게 있으면 **카드와
상세 화면에 별도로 경고를 노출**합니다. 총점·등급·통과 여부에는 전혀 영향을 주지
않습니다 — 상승 초입에도 RSI 단기 과열 같은 경보가 섞여 나올 수 있어서, 종목째로
빼면 좋은 진입 기회까지 함께 날아가기 때문입니다. 최종 판단은 사람이 합니다.

| 감지 항목 | 조건 (매수 조건의 정반대) |
|---|---|
| 이동평균 역배열 전환 | 20MA < 60MA + 20MA 5일 기울기 하락 |
| 지지선 이탈 | 종가가 60일 최저가의 102% 이내로 근접 |
| 대량 거래 하락 | 하락률 1.5% 이상 + 거래량 평균의 1.5배 이상 |
| RSI 과열 후 하락 전환 | RSI 70 초과 + 전일 대비 하락 |
| MACD 데드크로스 | 최근 3봉 이내 MACD가 시그널선을 하향 돌파 |
| 하락 추세에 힘 실림 | ADX 20 이상 + −DI > +DI |
| OBV 하락 | OBV 20봉 변화율 −5% 미만 |

텔레그램·이메일 알림과 대시보드 표 보기에도 함께 표시됩니다.

## 초보자를 위한 화면 구성

투자를 처음 하는 사람이 봐도 판단 근거를 알 수 있게 만들었습니다.

- **등급 해설** — S·A·B·C가 각각 무슨 뜻이고 무엇을 주의해야 하는지 상세 화면 맨 위와
  가이드 탭에 나옵니다. 등급은 "오를 확률"이 아니라 "차트가 매수 조건에 얼마나
  부합하는가"라는 점을 명시합니다.
- **지표별 실제 수치** — 8개 지표마다 점수만이 아니라 계산에 쓰인 숫자를 그대로 보여줍니다.
  예: 20일 평균선 23,762 / 이격 +10.4% / 당일 거래량 13.4만주 / 20일 평균 8.2만주 /
  평균 대비 1.63배 / RSI 70.3 (전일 67.2, +3.1) / +DI 53.2 > −DI 17.4.
- **"이 지표가 뭔가요?"** — 지표마다 접이식 해설이 붙습니다.
- **한 줄 요약** — 카드마다 "상승 추세 · 거래량 급증 · 저항 돌파"처럼 충족 조건을
  비중 큰 순으로 표시합니다.
- **가이드 탭** — 등급 의미, 앱 쓰는 순서 5단계, 초보자가 손실 보는 5가지,
  지표 8개 한눈에, 용어 사전, **이 앱이 알려주지 못하는 것**.
- **알림에도 반영** — 텔레그램·이메일에 한 줄 요약, 등급 안내, 손익비 경고가 함께 갑니다.

> 결과 JSON은 종목당 약 4.7KB입니다. 상한 200종목일 때 원본 850KB / gzip 82KB로,
> GitHub Pages가 압축 전송하므로 모바일에서도 가볍습니다. 상한을 넘으면 몇 건을
> 제외했는지 로그와 화면에 명시합니다.

## 종목 → 차트 바로가기

목록의 종목 카드마다 아래쪽에 "📈 차트 보기 ↗" 링크가, 상세 화면 상단에는
"📈 차트 보기" 버튼이 붙어 있습니다. 눌러서 새 탭이 열리면 그 종목의 실제
캔들 차트를 바로 볼 수 있습니다(표 보기에서는 각 행 오른쪽의 "↗"입니다).

- **국내**: 네이버 증권(모바일) — `https://m.stock.naver.com/domestic/stock/{종목코드}/total`
- **미국**: 거래소 매핑이 있으면 네이버 해외주식, 없으면 야후 파이낸스로 자동 연결됩니다
  (`screener/sources/us_stock.py`의 `link_for()`). 클래스주(`BRK.B`)처럼 네이버
  표기 규칙이 다른 경우는 안전하게 야후로 보냅니다.
- **코인**: 업비트 — `https://upbit.com/exchange?code=CRIX.UPBIT.{마켓코드}`

링크는 데이터 수집 단계(`screener/run.py`)에서 종목마다 계산해 JSON에
`link` 필드로 담기고, 프론트엔드는 그 값을 그대로 새 탭 링크로 씁니다. 카드
자체는 여전히 클릭하면 상세 분석 모달이 열리며, 차트 링크는 카드 바깥의
별도 줄이라 서로 동작이 섞이지 않습니다.

## 조건 밖 종목도 이름으로 검색

애플·아마존·테슬라처럼 매수 조건(최소 점수·등급)을 만족하지 못해 카드
목록엔 안 뜨는 종목도, 검색창에 이름이나 티커를 치면 찾을 수 있습니다.

- **검색 범위**: 각 시장에서 실제로 스캔되는 전체 종목 — 국내는 코스피·코스닥
  (시총·거래대금 하한 통과분), 미국은 S&P500+나스닥100, 코인은 업비트
  원화마켓 전체입니다. 애초에 스캔 대상이 아닌 종목(상장폐지, 목표 시장 밖
  종목 등)은 검색되지 않습니다.
- **보여주는 정보**: 현재가·등락률·총점·등급과 차트 바로가기까지만 —
  8개 지표 상세 breakdown은 카드 목록에 뜨는(조건을 만족하는) 종목에서만
  제공됩니다. 검색 결과 카드는 점선 테두리로 구분되고, 모달에도 "조건을
  만족하지 못해 목록에 없다"는 안내가 함께 뜹니다.
- **구현**: `screener/run.py`가 채점에 성공한 모든 종목의 기본 정보를
  `search_index` 배열로 JSON에 함께 담습니다(점수 미달 여부와 무관하게).
  프론트엔드는 검색어가 있을 때만 이 배열에서 현재 목록에 없는 종목을
  걸러 "조건 밖 검색 결과" 섹션에 최대 20건 보여줍니다.

> `search_index`는 지표 상세 없이 기본 필드만 담아 종목당 200바이트
> 안팎이라, 시장 전체(국내 수백~천여 종목, 미국 약 550종목, 코인
> 수백 종목)를 더해도 gzip 전송 기준으로는 부담이 크지 않습니다.

## 추세전환 초기탐지 — 새 탭 "추세전환"

기존 매수신호 탭은 **이미 상승 추세인** 종목을 찾습니다. 그와 반대로, 각 시장
탭(국내주식·미국주식·코인) 안에는 **"매수신호" / "추세전환"** 두 개 콘텐츠
토글이 있고, "추세전환"을 누르면 **장기간 하락하던 종목이 하락을 멈추고 상승으로
돌아서는 초기 구간**을 찾아 보여줍니다.

목표는 "바닥을 정확히 맞추는 것"이 아니라, *하락 추세 → 하락세 둔화 → 바닥
형성 → 초기 상승 전환*이라는 과정을 여러 독립 지표로 나눠 점수화해서 다른
사람보다 먼저 후보를 좁히는 것입니다. 그래서 RSI 30 이하, MACD 골든크로스 같은
지표 하나만 보고 판단하지 않고, 아래 6개 카테고리를 전부 독립적인 증거로 취급해
합산합니다 (`screener/reversal.py`).

**대상 조건**: 최근 120봉(≈6개월) 고점 대비 **15% 이상 하락**한 종목만 봅니다.
이미 상승 추세이거나 하락폭이 미미한 종목까지 "반전 후보"로 잡으면 매수신호
탭과 겹치고 노이즈만 늘어나기 때문입니다.

| 카테고리 | 배점 | 신호 |
|---|---|---|
| 가격 구조 | 25점 | 신저가 발생 실패 · Higher Low 형성 · 직전 Swing High 돌파 · 장기 하락추세선 돌파 |
| 거래량 | 20점 | 하락 거래량 감소 · 상승 시 거래량 증가 · 거래량 돌파 · OBV 상승 다이버전스 |
| 모멘텀 | 20점 | RSI 상승 다이버전스 · MACD 상승 다이버전스 · MACD 히스토그램 개선 · 스토캐스틱 반전 |
| 이동평균 | 15점 | 20일선 회복 · 20일선 하락세 종료 · 20일선 상승 전환 · 60일선 회복 |
| 변동성/시장구조 | 10점 | ATR 수축 후 확대 · 볼린저밴드 수축 후 상방 돌파 · 저점 변동성 구조 변화 |
| 코인 특화 | 10점 | BTC 대비 상대강도 (코인 탭에서만, 아래 설명 참고) |

주식(코인 특화 신호가 없는)은 90점 만점을 100점으로 재환산합니다 — 기존
타임프레임 결합 로직(`score.py`)이 데이터가 없는 타임프레임의 비중을 나머지에
재분배하는 것과 같은 방식입니다.

### 초기 진입 vs 확인 진입

가장 중요한 구분입니다.

- **확인 진입** — 가격이 실제로 **직전 반등 고점(저항)을 돌파**해, 하락 추세가
  구조적으로 꺾였다는 게 데이터로 확인된 상태입니다. 늦게 들어가는 대신
  다시 신저가로 미끄러질 위험은 상대적으로 낮습니다.
- **초기 진입** — 아직 돌파 전이지만, 신저가 실패·다이버전스·거래량 변화 같은
  사전 신호가 여러 개 겹치기 시작한 상태입니다(반전점수 35점 이상). 가장 먼저
  잡을 수 있는 대신 되돌림(가짜 반등)에 걸릴 위험이 가장 큽니다.

### "왜 이 종목인가"

카드를 눌러 상세를 열면 충족된 신호를 배점·근거 문장과 함께 전부 보여줍니다
(예: "가격 저점은 낮아졌지만 RSI는 상승(28→41) — 상승 다이버전스, +7.0점").
가격구조·거래량·모멘텀·이동평균·변동성 5(코인은 6)개 카테고리별 획득 점수도
막대로 보여주고, 접이식 "평가한 신호 N개 전부 보기"에서 충족하지 못한 신호까지
포함한 전체 목록을 확인할 수 있습니다.

### 이번에 뺀 것 — 코인 파생상품 데이터

원 스펙에는 코인 특화 신호로 **Funding Rate·Open Interest·롱숏비율·청산
데이터**도 있었습니다. 하지만 이 앱이 쓰는 업비트는 **현물(spot) 전용
거래소**라 애초에 파생상품 데이터를 제공하지 않습니다. 이 신호들을 쓰려면
바이낸스 등 별도 선물 거래소 API를 새로 붙여야 하는데, 거래소 간 종목 코드
매핑(업비트 `KRW-XXX` ↔ 선물 거래소 `XXXUSDT`), 별도 인증·요청 한도 관리,
상장 종목 불일치 처리까지 검증이 필요한 작업이라 안정성이 검증되지 않은 채
자동화 파이프라인에 끼워 넣는 리스크가 크다고 판단해 이번 범위에서 뺐습니다.
**BTC dominance**(전체 코인 시총 대비 BTC 비중 추이)도 무료로 안정적인
과거 시계열을 주는 API가 마땅치 않아 함께 뺐습니다. 대신 이미 갖고 있는
업비트 시세만으로 신뢰성 있게 계산되는 **"BTC 대비 상대강도"**(최근 20일
수익률을 BTC와 비교)를 코인 특화 10점 전부에 씁니다 — 코인 스크리닝 때
`KRW-BTC` 일봉을 한 번만 받아 모든 코인이 재사용합니다. 이 부분은 추후
별도 거래소 연동이 안정적으로 검증되면 확장할 수 있는 지점으로 남겨둡니다.

> 오프라인 미리보기(`--market demo`)에도 급락 후 바닥을 다지는 합성 종목
> 6개가 함께 생성되어, 네트워크 없이도 추세전환 탭 화면을 확인할 수 있습니다.

⚠ 이 점수 역시 매수 권유가 아닙니다. 특히 "초기 진입"은 정의상 아직 하락
추세 안에 있던 종목이라 가장 위험도가 높은 구간입니다. 분할 진입과 손절선은
반드시 스스로 정하세요.

## 내 전략 — 지표 비중을 직접 조절하는 탭

매수신호·추세전환 탭의 점수는 `config.py`에 적힌 **고정 비중**으로 계산됩니다.
합리적인 기본값이지만 사람마다 믿는 지표가 다릅니다. 거래량과 OBV만 보는 사람에게
그 화면의 1위는 남의 1위입니다.

**내 전략** 탭은 그 비중을 사용자가 직접 바꾸고, 브라우저에서 **전 종목을 다시**
줄 세웁니다.

### 왜 별도 파일이 필요한가

`{market}_latest.json`에는 **55점 이상 상위 200종목**의 지표 상세만 들어 있습니다.
그 200종목 안에서만 순서를 바꾼다면 이 기능은 반쪽입니다 — 내 비중으로 90점이 될
종목이 그 밖에 있을 수 있기 때문입니다.

그래서 평가에 성공한 **전 종목**의 지표별 원점수를 담은
`docs/data/{market}_matrix.json`을 따로 만들고, 사용자가 이 탭을 **처음 열 때만**
받습니다. 매수신호·추세전환 탭의 첫 로딩 속도는 그대로입니다.

| 시장 | 종목 수(추정) | 원본 | gzip 전송 |
|---|--:|--:|--:|
| 국내주식 | 약 1,800 | 약 200 KB | 약 77 KB |
| 미국주식 | 약 600 | 약 67 KB | 약 26 KB |
| 코인 | 약 180 | 약 20 KB | 약 8 KB |

파일 구조는 키 이름을 종목마다 반복하지 않도록 **위치 기반 배열**입니다.
스키마는 파일 안 `row_fields`가 설명합니다.

```jsonc
"row_fields": ["symbol","s_1d","s_1w","okmask","turnover_m","rr","atr_pct","warn"],
"rows": [["005930",[81.7,74.0,…8개],[59.1,…8개],173,312000,2.84,3.1,0], …]
```

### 재계산은 서버와 같은 공식

브라우저가 `screener/score.py`의 계산을 그대로 다시 합니다 — 타임프레임 결합과
정렬 보너스(+5)까지 포함해서.

```
W            = Σ w[지표]                       ← 합계가 100이 아니어도 자동 정규화
tf_total[tf] = Σ ( 지표점수[tf] × w[지표] ) / W
combined     = Σ tf_total[tf] × tf비중 / Σ tf비중   ← 데이터 없는 tf는 빼고 재정규화
모든 tf ≥ 60 (2개 이상)  →  +5점
```

그래서 **프리셋을 "기본(교과서)"으로 두면 내 전략 탭의 순서가 매수신호 탭과
완전히 같아집니다.** 이 일치가 이 기능 전체의 신뢰 근거이고, 테스트로 고정해
두었습니다.

```
tests/test_custom.py::test_default_weights_reproduce_official_score    # 오차 < 0.1점
tests/test_custom.py::test_default_weights_reproduce_official_ranking  # 순서까지 동일
```

실측 오차는 **0.027점**입니다(지표 점수를 소수 1자리로 반올림해 담는 데서만 발생).

### 화면

- **기준 선택** — 매수신호(지표 8개) / 추세전환(카테고리 6개)
- **전략 프리셋** — 매수신호 7종(기본·추세추종·돌파·눌림목·수급중심·모멘텀·균형),
  추세전환 5종(기본·구조우선·다이버전스·거래량소진·코인상대강도).
  슬라이더를 열지 않아도 기능을 다 쓸 수 있습니다.
- **직접 조절** — 접이식 슬라이더. 합계를 100에 맞출 필요가 없습니다.
- **필수 조건** — 비중으로는 못 거르는 것들: 거래대금·손익비·경고 신호 개수·당일
  등락률 상한·ATR 상한. **어느 조건이 몇 건을 걸렀는지** 타일과 빈 화면 문구에
  그대로 나옵니다.
- **카드** — 순위 배지(#1) + `내 점수 88.4 · 기본 71.3 (▲38위)`.
  기본 목록에 없던 종목은 `새로 발굴` 표시.
- **상세** — "왜 내 설정에서 올라왔나"(기여도 델타를 문장으로) + 지표별 기여도 막대
  (회색 눈금이 기본 비중 위치) + 기존 8지표 수치.
- **저장 · 공유** — 조합 5개까지 이 기기에 저장(메모 포함), `#s=…` 해시로 링크 공유.
  저장은 `localStorage`에만 하며 어디로도 전송되지 않습니다.

### 등급을 붙이지 않는 이유

커스텀 점수에는 S·A·B·C를 **붙이지 않습니다.** 등급은 "기본 비중 기준"이라는 뜻을
갖는데, 직접 만든 점수에 S를 붙이면 사용자가 스스로 만든 S등급을 신뢰하게 됩니다.
대신 순위(#1)를 쓰고 카드마다 기본 점수를 나란히 보여줍니다.

### 과최적화 방지 장치

이 기능은 잘못 쓰면 "마음에 드는 종목이 1위가 될 때까지 슬라이더를 돌리는 기계"가
됩니다. 그래서 다섯 가지를 넣었습니다.

1. 모든 카드에 **기본 점수 병기** — 내 설정이 기본에서 얼마나 벗어났는지 항상 보인다
2. 한 지표에 **40% 초과**가 몰리면 노란 편중 경고
3. **등급 미부여** (위 참조)
4. 저장할 때 **"왜 이 비중인가" 메모** 유도
5. 가이드 고정 문구 — *"비중은 결과를 보고 맞추는 게 아니라, 먼저 매매 논리를 정하고
   그 논리를 숫자로 옮기는 도구입니다."*

### 아직 없는 것

**과거 성과 검증(간이 백테스트)** — 현재 `docs/data/history/`에는 상위 60종목의 일부
필드만 보관해 재계산이 불가능합니다. 하려면 히스토리 포맷부터 확장해야 합니다.
자세한 설계는 [`PLAN-my-strategy.md`](PLAN-my-strategy.md) §10 Phase 4를 보세요.

## 튜닝

거의 모든 설정은 [`screener/config.py`](screener/config.py) 한 파일에 있습니다.

```python
WEIGHTS = {"ma": 25, "volume": 20, ...}   # 가중치 (합 100)
GRADE_CUTS = [("S", 85), ("A", 75), ...]  # 등급 컷
KR_MIN_MARKETCAP = 50_000_000_000         # 시총 500억 미만 제외
KR_MIN_TURNOVER  = 100_000_000            # 거래대금 1억 미만 제외
US_MIN_PRICE     = 5.0                    # 미국주식 5달러 미만 제외
US_MIN_TURNOVER  = 20_000_000             # 20일 평균 거래대금 2천만 달러 미만 제외
MAX_RR_TARGET    = 5.0                    # 1차 목표가 상한 (손절폭의 몇 배까지)
COIN_MIN_TURNOVER_24H = 500_000_000       # 코인 24h 거래대금 5억 미만 제외
TF_WEIGHTS = {"kr": {"1d": 0.70, "1w": 0.30}, ...}
REV_MAX_OUTPUT_ITEMS = 150                # 추세전환 후보 저장 상한

WEIGHT_PRESETS = {...}                    # 내 전략 탭 프리셋 (합 100, 테스트가 검증)
REV_WEIGHT_PRESETS = {...}                # 추세전환 기준 프리셋
HARD_FILTER_DEFS = [...]                  # 필수 조건 선택지
WEIGHT_CONCENTRATION_WARN = 40            # 한 지표 비중이 이 %를 넘으면 편중 경고
```

프리셋을 고치면 배포만으로 사용자 화면에 반영됩니다(매트릭스 파일에 함께 실려 나갑니다).
`WEIGHT_PRESETS["default"]`는 반드시 `WEIGHTS`와 같아야 하며, 어긋나면 테스트가 막습니다.

수정 후 push하면 다음 실행부터 바로 반영됩니다.
지표별 점수 규칙 자체를 바꾸려면 [`screener/rules.py`](screener/rules.py)를 보세요.
각 함수가 `(점수, 설명, 조건충족여부)`를 돌려주는 단순한 구조입니다.

추세전환 점수(가중치·최소 하락률·진입 단계 컷)를 바꾸려면
[`screener/reversal.py`](screener/reversal.py) 상단의 `LOOKBACK_MAX`,
`MIN_DECLINE_PCT`, `EARLY_MIN_SCORE`, `CAT_MAX`를 보세요. 신호 하나하나가
`_sig_...` 함수로 분리돼 있어 배점이나 판정 기준만 따로 조정할 수 있습니다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| 대시보드가 "결과 파일이 없습니다" | 아직 워크플로를 한 번도 안 돌렸습니다. `Actions` → `Run workflow` |
| 워크플로가 push 단계에서 실패 | 4단계(Workflow permissions → Read and write)를 안 했습니다 |
| 코인 실행이 `HTTP 403/418`로 실패 | 업비트가 해외 서버 IP를 차단한 경우입니다. 진단 워크플로를 돌려 빗썸 가용 여부를 확인하세요 |
| 텔레그램이 안 옴 | 봇에게 **먼저 메시지를 보냈는지** 확인하세요. 안 보내면 봇이 대화를 시작할 수 없습니다 |
| `KRX 로그인 실패` 에러 | 옛 버전(pykrx 사용)입니다. 최신 코드로 교체하세요 — 이제 KRX를 쓰지 않습니다 |
| 국내주식 수집률이 낮음 | 로그의 `야후 수집 완료: N/M종목` 비율을 확인하세요. 50% 미만이면 자동으로 네이버로 재시도합니다 |
| 미국주식 종목 수가 적음 | 로그의 `유니버스 확정: N종목`을 보세요. 550 미만이면 목록 소스가 막혀 내장 스냅샷으로 돌아간 상태입니다. 동작에는 문제없습니다 |
| 미국주식 탭만 비어 있음 | 미국주식 워크플로를 아직 안 돌렸습니다. `Actions` → **미국주식 스크리닝** → `Run workflow` |
| 결과가 0건 | 하락장에서는 정상입니다. 대시보드 슬라이더를 55까지 내려보세요 |

## 안전장치 — 조용히 잘못되지 않도록

이 앱은 아무도 안 볼 때 새벽에 혼자 돕니다. 그래서 "틀린 결과를 자신 있게 보여주는"
실패가 제일 위험합니다. 다음 항목들을 명시적으로 막아뒀습니다.

**데이터가 조용히 사라지는 것**

- FinanceDataReader는 위키백과를 읽으며 심볼의 점을 지웁니다(`BRK.B` → `BRKB`).
  어느 사이트에도 없는 심볼이라 버크셔·브라운포맨이 **오류 하나 없이** 유니버스에서
  빠집니다. 점을 보존하는 CSV를 1순위로 두고, 내려가더라도 `normalize_symbols()`가
  되돌립니다.
- 야후 일봉은 액면분할을 소급 반영해서(`auto_adjust=True`) 받습니다. 끄면 분할일에
  −90% 같은 가짜 폭락이 남아 이동평균·RSI가 무너지고, 목표가가 현재가의 10배로
  계산됩니다.

**실행 결과가 통째로 날아가는 것**

- 예전에는 세 시장이 같은 `index.json`을 읽고-고쳐-썼습니다. 실행이 겹치면 git rebase가
  충돌하고, 재시도 루프가 그 충돌을 복구하지 못한 채 **초록불로 끝났습니다** —
  그날 히스토리 스냅샷은 영구 손실입니다. 공용 파일을 없애 시장별로 완전히 분리했고,
  커밋 단계는 충돌 시 `rebase --abort` 후 재시도하며 3회 실패하면 워크플로를
  실패시킵니다.
- 코인 실행 시각을 05분 → 20분으로 옮겨 국내주식·미국주식 실행 창을 피했습니다.

**같은 내용을 두 번 알리는 것**

- 미국 공휴일에도 크론은 돕니다. 마지막 봉 날짜가 직전 실행과 같으면 휴장일로 보고
  히스토리 저장과 알림을 건너뜁니다.
- `--market demo`는 합성 데이터라 히스토리를 절대 건드리지 않고 알림도 보내지 않으며,
  대시보드에 `샘플데이터`로 표시됩니다.

**보안**

- 종목명은 위키백과·네이버 같은 외부 사이트에서 옵니다. 대시보드·이메일·텔레그램의
  모든 삽입 지점을 이스케이프했고, 대시보드에는 CSP를 걸어 외부 스크립트 로드와
  다른 출처로의 통신을 차단했습니다.
- 텔레그램 오류 로그에 예외 메시지를 그대로 찍지 않습니다 — 요청 URL에 봇 토큰이
  들어 있어 Actions 로그로 흘러갈 수 있습니다.
- 워크플로의 `${{ github.ref_name }}`를 셸에 직접 펼치지 않고 환경변수로 받아
  인용합니다(스크립트 인젝션 차단). 테스트·진단 워크플로는 `contents: read`로
  권한을 좁혔습니다.

**표시**

- 손익비는 손절폭의 5배로 상한을 둡니다. 고점 대비 반토막 난 종목이 "직전 고점"을
  목표로 잡아 손익비 15짜리 좋은 자리처럼 보이던 문제를 막습니다.
- 오프라인에서는 저장해 둔 마지막 결과를 보여주고, 저장본이 없으면 "결과가 없다"가
  아니라 "지금 오프라인"이라고 정확히 말합니다.
